# Pipeline 与 Hybrid 离线现场部署指南

## 一、部署架构

```text
客户端 -> Router:8002 -> API-1:18000
                           ├─ pipeline -> 本地 PDF-Extract-Kit-1.0
                           └─ hybrid-http-client -> 本地 Pipeline + 外部 VLM:30000
```

现场是无网络的麒麟 ARM/NPU 环境。任何模型下载、Git 拉取和镜像构建都必须在进场前完成。

## 二、进场前交付物检查

```text
docker/multi/
├── artifacts/mineru-pipeline-models-3.4.2.tar.gz
├── artifacts/mineru-pipeline-models-3.4.2.tar.gz.sha256
├── images/mineru-env-npu-v1.0.tar.gz
├── images/mineru-code-v3.4.2.tar.gz
├── compose-multi.yaml
├── env.multi.example
├── mineru.pipeline.json
├── start-multi.sh
└── test.pdf（或其他小型测试 PDF）
```

来源必须明确：

- Pipeline 模型归档：联网 WSL 使用 `prepare-pipeline-models.sh` 生成；
- `mineru-code`：联网 ARM/NPU 服务器从 GitHub 拉取相同代码版本后构建；
- `mineru-env`：同一服务器使用与现场 CANN/驱动配套的 Ascend PyTorch 基础镜像构建并完成 NPU 验证；
- 外部 VLM：现场已有或另行部署，本 Compose 不创建 VLM。

## 三、校验并解压模型

```bash
cd /path/to/docker/multi/artifacts
sha256sum -c mineru-pipeline-models-3.4.2.tar.gz.sha256

cd ..
mkdir -p models/PDF-Extract-Kit-1.0
tar -xzf artifacts/mineru-pipeline-models-3.4.2.tar.gz \
  -C models/PDF-Extract-Kit-1.0
```

解压后的层级必须是：

```text
models/PDF-Extract-Kit-1.0/models/Layout/PP-DocLayoutV2/
models/PDF-Extract-Kit-1.0/models/MFR/unimernet_hf_small_2503/
models/PDF-Extract-Kit-1.0/models/MFR/pp_formulanet_plus_m/
models/PDF-Extract-Kit-1.0/models/OCR/paddleocr_torch/
models/PDF-Extract-Kit-1.0/models/TabRec/SlanetPlus/slanet-plus.onnx
models/PDF-Extract-Kit-1.0/models/TabRec/UnetStructure/unet.onnx
models/PDF-Extract-Kit-1.0/models/TabCls/paddle_table_cls/PP-LCNet_x1_0_table_cls.onnx
```

## 四、配置

```bash
cp env.multi.example env.multi
```

重点修改：

```dotenv
MINERU_ENV_IMAGE=mineru-env:npu-v1.0
MINERU_CODE_IMAGE=mineru-code:v3.4.2
PIPELINE_MODEL_HOST_PATH=./models/PDF-Extract-Kit-1.0
PIPELINE_CONFIG_HOST_PATH=./mineru.pipeline.json
MINERU_MODEL_SOURCE=local

VLM_1_IP=现场外部VLM的实际IP
VLM_1_PORT=30000
MINERU_VLM_MODEL=外部VLM的实际模型名
```

`VLM_1_IP` 不能填写 `127.0.0.1` 或 `localhost`。模型名以 VLM `/v1/models` 返回值为准。

设备模式分两种：

- Pipeline 使用 NPU：`mineru-env` 必须包含与现场 CANN 匹配的 `torch_npu`，并设置 `MINERU_DEVICE_MODE=npu` 和 `PIPELINE_NPU_ID=6`。
- `compose-multi.yaml` 会手工映射指定的 `/dev/davinciN`、公共管理节点以及宿主机 Ascend 驱动目录；启动前必须确认这些路径存在。

## 五、导入镜像

```bash
./start-multi.sh import-images
docker image inspect mineru-env:npu-v1.0 --format '{{.Architecture}}'
docker image inspect mineru-code:v3.4.2 --format '{{.Architecture}}'
```

现场应输出 `arm64`。如果输出 `amd64`，镜像架构错误，不能继续启动。

## 六、检查并启动

```bash
./start-multi.sh check
./start-multi.sh start
./start-multi.sh status
```

`check` 会验证：

1. Compose 和 `env.multi`；
2. 两个镜像标签；
3. 七组 Pipeline 模型；
4. `mineru.pipeline.json` 和容器内模型挂载；
5. API 容器到外部 VLM 的 `/v1/models` 连通性。

## 七、测试 Pipeline 和 Hybrid

```bash
./start-multi.sh test /path/to/test.pdf
```

也可以分别调用：

```bash
curl -f -X POST http://127.0.0.1:8002/file_parse \
  -F "files=@/path/to/test.pdf" \
  -F "backend=pipeline"

curl -f -X POST http://127.0.0.1:8002/file_parse \
  -F "files=@/path/to/test.pdf" \
  -F "backend=hybrid-http-client"
```

第一次请求会加载模型，耗时明显高于后续请求。健康检查成功不等于模型链路成功，必须完成上述解析请求。

## 八、修改配置后重建容器

模型挂载、环境变量或设备映射变化后执行：

```bash
./start-multi.sh stop
./start-multi.sh check
./start-multi.sh start
```

## 九、故障定位

```bash
docker logs -f mineru-api-1
docker logs -f mineru-router
npu-smi info
```

- `缺少 Pipeline 模型`：解压层级错误或归档不完整；
- `容器内缺少模型`：检查挂载路径，或确认归档已解引用符号链接；
- VLM `/v1/models` 失败：检查 VLM 地址、监听地址、防火墙和模型名；
- NPU 不可用：检查环境镜像、CANN/torch_npu 版本、设备节点和驱动挂载；
- `Read-only file system`：保持输出目录为 `/var/lib/mineru/output`。
