# MinerU 离线现场交接上下文

本文用于新会话中的 Codex 快速恢复真实环境和交付链路。不要把三处机器混为一谈。

## 1. 三处环境

### A. 开发 WSL

- 当前仓库路径：`/home/sgy/workspace/MinerU`；
- 已确认架构：`x86_64`，WSL2；
- 有网络，已安装 `uv`；
- Git 分支：`dev`；
- GitHub 远程：`origin=git@github.com:StanlySGY/MinerU.git`；
- 职责：修改代码和部署文件、提交到 GitHub、下载 Pipeline 模型、生成离线模型归档；
- 不负责构建最终现场使用的 ARM64 `mineru-code` 镜像。

WSL 下载并打包模型：

```bash
cd /home/sgy/workspace/MinerU/docker/multi
./prepare-pipeline-models.sh
```

输出：

```text
artifacts/mineru-pipeline-models-3.4.2.tar.gz
artifacts/mineru-pipeline-models-3.4.2.tar.gz.sha256
```

准备好 ARM code 镜像和现场 env 镜像后，在 WSL 将整个目录打包交付：

```bash
cd /home/sgy/workspace/MinerU/docker
tar -czf mineru-offline-multi.tar.gz -C . multi
sha256sum mineru-offline-multi.tar.gz > mineru-offline-multi.tar.gz.sha256
```

### B. 公司联网 ARM CPU 服务器

- 架构：ARM64/aarch64；
- 有网络；
- 与 WSL 之间通过 GitHub 同步代码，不依赖直接文件连接；
- 职责：拉取 WSL 推送的同一 Git 提交，构建并导出现场需要的 ARM64 `mineru-code` 镜像；
- 不负责 Pipeline 模型下载，模型由 WSL 打包。

参考命令：

```bash
git fetch origin
git switch dev
git pull --ff-only origin dev

cd docker/base
MINERU_CODE_TAG=v3.4.2 ./build.sh code
MINERU_CODE_TAG=v3.4.2 \
MINERU_EXPORT_DIR=/data/mineru-export \
  ./build.sh export-code

docker image inspect mineru-code:v3.4.2 --format '{{.Architecture}}'
sha256sum /data/mineru-export/mineru-code-v3.4.2.tar.gz \
  > /data/mineru-export/mineru-code-v3.4.2.tar.gz.sha256
```

架构检查应输出 `arm64`。

### C. 离线现场

- 操作系统：麒麟；
- 架构：ARM64；
- 有 NPU 环境；
- 完全无网络，不能 Git 拉取、pip/uv 安装或在线下载模型；
- 职责：校验归档、导入镜像、解压模型、配置、启动、测试 `pipeline` 和 `hybrid-http-client`。

## 2. 最终数据流

```text
WSL(x86_64, 有网)
  ├─ Git push ----------------------> ARM CPU 服务器(arm64, 有网)
  │                                   └─ 构建 mineru-code:arm64
  └─ 下载/打包 Pipeline 模型

模型归档 + ARM code 镜像 + ARM/NPU env 镜像 + docker/multi
  └────────────────────────────────> 麒麟 NPU 现场(arm64, 无网)
```

## 4. 已确定的部署行为

- `backend=pipeline`：API 使用本地 Pipeline 模型；
- `backend=hybrid-http-client`：API 同时使用本地 Pipeline 模型和外部 OpenAI 兼容 VLM；
- Compose 不负责创建外部 VLM；
- Pipeline 模型在容器内固定挂载到 `/models/pipeline`；
- 最小配置在容器内固定挂载到 `/etc/mineru/mineru.json`；
- `MINERU_MODEL_SOURCE=local`，现场禁止联网下载；
- 模型或挂载变化后必须重新创建 API 容器。

## 5. 关键风险和未确认项

1. `mineru-env:v1.0` 的来源和兼容性必须确认。它需要是 ARM64，并包含现场 Pipeline 所需依赖；若 Pipeline 使用 NPU，还必须匹配现场 CANN 和 `torch_npu`。
2. 当前 `compose-multi.yaml` 尚未加入特定现场的 NPU 设备节点和驱动挂载。CPU 功能测试可以先做；NPU 启用前必须根据现场设备补配置。
3. `MINERU_VLM_MODEL` 必须与现场外部 VLM `/v1/models` 返回值一致，不能仅沿用示例值。
4. GitHub 只连接 WSL 和公司 ARM 服务器；现场没有 GitHub，也不应设计任何现场下载步骤。
