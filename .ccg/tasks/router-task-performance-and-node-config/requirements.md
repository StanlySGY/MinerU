# 需求

来源:现场运维控制台审查,六个问题(任务/监控/取消/布局/列宽/数据源)。用户授权一并改掉并构建 ui22。

## 1. 删除缓存后不再死循环(#3,现场必踩)

- 详情加载失败时不得让 10 秒轮询反复重试一个服务端已经没有的任务。
- 任务确实不存在(404 / task unavailable)时,清掉详情选中态和 URL 里的 `taskId`,并给出一次明确提示。
- 「删除缓存」成功后同样要清 URL 里的 `taskId`。
- 任务已被终止 / 超出保留期时,SSE 只推一次就收尾,不能每秒重新问一个不存在的任务。

## 2. 可以真正终止任务(#4,新增能力)

三层都要有入口:

- API(`mineru/cli/fast_api.py`):`DELETE /tasks/{task_id}`。排队中的任务不再被启动;运行中的任务要真正中断正在跑的解析协程;终态里新增 `cancelled`。
- Router(`mineru/cli/router.py`):`DELETE /tasks/{task_id}`。把取消转发给承接该任务的上游 API,然后丢掉本地记录;上游不可达时保留记录并报 502,避免任务还在跑但控制台再无句柄。
- 控制台:`POST /api/tasks/{task_id}/cancel`。Router 确认后才清缓存;Router 失败时不删缓存,免得页面显示的"已取消"是假的。
- UI:详情面板加「终止任务」,只对未结束的任务显示,确认文案写明会中断解析且不可撤销;点击后清选中态并刷新列表。

## 3. 任务列表不再被挤掉列(#2 与 #5)

- 列表表格自己滚动(表头吸顶),横向滚动条留在视口内,不再被 100 行高度推到屏幕外。
- 时间/数值/后端列有最小宽度,不被压扁到读不出来。
- 左右并排放不下时(七列任务表约需 735px)改为上下堆叠,列表拿满宽度,详情下移。

## 4. 总览计数覆盖全部任务(#6)

- 计数走服务端聚合(`COUNT(*) GROUP BY status`),不再只数列表前 100 条。
- 总览与任务页看到的是同一批任务的两种密度,计数与列表口径一致。

## 5. 列表与批次接口瘦身(现场"卡"的根因)

- `/api/tasks` 列表不再逐页返回 `progress.files[].pages`(实测占单条快照约 98%);详情接口保留完整数据。
- `/api/overview` 不再为几个计数拉 100 条完整任务。
- 批量指标不再整包返回 `page_samples`,只给数量和精简后的最慢页。
- 服务探测与产物体积统计加短 TTL 缓存,避免每个打开的页面每 10 秒重算一遍。

## 验收

- Python 单测全绿;JS 语法检查通过。
- 用真实 Router + 上游桩跑通"控制台终止 → Router → 上游"整条链路,并确认上游任务真的消失。
- 浏览器实测:各视口下列全部可见可滚、表头吸顶、删除缓存后不再重复请求、终止任务后列表和 Router 都已清掉。
